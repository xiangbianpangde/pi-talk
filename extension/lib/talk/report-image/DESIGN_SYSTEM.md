# 图像汇报设计系统 · Fieldnote

**状态：** 原生 `/talk` 正式汇报图像模式；与 HTML `report` 样式互斥。生成路径为结构化内容 → 安全 SVG → 无头 Chromium PNG，不依赖 Codex/MMX 的绘图质量和在线服务。SVG 与 PNG 同目录保留，便于复核与再编辑。

## 版面与语义

- 画布固定 **1200 × 1600 px**，3:4 竖版；每次由用户选择 **1–5 张**，默认建议 1 张。每张自成一页，页码 `01 / 0N`；不把超长文案缩成不可读小字。
- 阅读顺序：眉题和页码 → 标题 → 深绿核心结论 → 已验证指标（可缺省）→ 2–4 个分析卡 → 1–3 项证据链 → 边界和来源。单张完整覆盖“结论—依据—限制”。多张分别呈现主题，不拆断单页证据链。
- 色彩：暖纸 `#f7f3e9`，深墨 `#25312f`，决策红 `#a83832`，证据绿 `#214d42`，次级文字 `#586862`。无渐变、阴影或素材依赖，靠色块、字阶和留白建立层次。
- 字体：优先苹方 / Noto Sans CJK SC / 微软雅黑，最后回退 Arial。标题 65px、结论 34px、卡片标题 24px、正文 19–21px。图文直接嵌入 SVG，离线可看；浏览器的字体回退可能影响排版，交付前必须目视检查 PNG。
- 指标只容纳可核验的事实；未提供指标时显示定性的阅读线索，不造数字。`source` 填具体文件、测试、数据集或 URL；`caveat` 强制写局限或适用范围。图片上所有文本为输入数据，经 XML 转义，不接受任意 SVG/HTML、脚本或远程素材。

## 内容预算与失败策略

工具 `talk_report_images` 的 `pages` 数量必须与提问时用户所选一致。单页要求 `kicker/title/takeaway/evidence/caveat/source`，`insights` 可按实际信息价值提供 0–4 条，可选 `metrics`。上限：标题 34 字、结论 95 字、4 张卡（标题 24、正文 80）、3 条证据（每条 52）；实际换行以字形宽度近似计算，超过容器行数直接拒绝，不静默裁切。内容过多时先重写摘要；若需要更多页面，重新征询用户，不绕过选定数量。

图像模式复用任务完成和验收通过的 `talk_prepare_report` 一次性许可；用户取消不出图。批量全部转换并核对 PNG 尺寸后才消费许可；任一失败删除整个批次并允许修正重试。生成文件位于会话 `exports/image-report-*/`，每页一份 `.svg` 和 `.png`。与 HTML 报告互不通用，HTML 许可不能用于图片，反之亦然。

## 交付验收

1. 实际张数等于用户选择且在 1–5；每张 PNG 1200×1600，文件头有效，SVG 源可追溯。
2. 逐张检查标题、数值、证据来源、边界是否真实且与内容一致；用图像查看器或读取 PNG 检查裁切、重叠、字体回退与可读性。
3. 不以 HTML 长截图伪装单页图，也不在未完成任务时发表正式图像汇报。
